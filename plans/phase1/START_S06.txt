二、冻结的数据契约与判断

P1-26 接口固定：async describe_image_for_index(image_path, *, source_file, page=None, location=None)。返回 dataclass 或 dict 均可，投影字段严格为 text/content_kind/source_file/page/location/asset_ref/skip_reason，符合 schemas.json 的 ImageDescription；content_kind=image_description。成功 text 非空且前缀明确“来自图像”，skip_reason=null；跳过 text=""，skip_reason 为 C09 五枚举之一。source_file 为可信原文件名；page 仅 parser 真实页索引（保持其语义、不猜 0/1 基），缺失 null；location 缺失 null。拒绝错误类型，不把任意对象 str() 成来源。不在 metadata 存 base64、密钥、绝对缓存路径、异常原文或半截回答。parser 资产标识由 loader 对受约束 asset root 求真实相对路径；独立图片用文件名。不能拿 asset 文件名猜页码。

沿用 settings/vision_strategy.py 的现有语义，不改 schema：auto 先能力允许的 main，明确不支持则 dedicated；main optimistic 图片请求被供应商拒绝时可尝试一次已配置 dedicated，再失败则 vision_failed，不静默生成无图文字。prefer_dedicated 与 dedicated_only 在当前代码是同义策略：只用 dedicated，缺配置 vision_unavailable，不能回 main。使用 resolve_vision_runtime_config() 取 dedicated，用现有 main config/capability resolver 判断 main。已有 LLMClient.complete() 只返回字符串，会丢失 finish_reason；新 helper 使用现有 factory.complete_response(...image_data/image_mime_type/image_filename...)，复用 validate_subject_response，再投影结果，不改 SDK/配置模块。限制输出预算、超时和候选尝试次数，不无限重试。空、正文截断、空截断、超时、供应商异常都不能作为成功文本节点；公开为 vision_failed，内部测试/固定诊断可区分，不返回异常原文。配置不可用归 vision_unavailable，预算归 budget，格式/损坏图片归 unsupported_image；取消仍向上传播。

文本 embedding 分支产出普通文本 Document，经现有文本 embedding/index/search 流程检索；不能把描述当成 image vector，也不更换模型、维度、signature 或全局 LlamaIndex 配置。原 multimodal embedding 的 ImageNode 路径保留有效图片、真实 embedding 和来源。现有 parser 选择和 asyncio.to_thread 保留；没有资产的 parser 只作覆盖不确定记录，不强行调用其他引擎/安装工具/重复解析补全全部图。loader.load() 保持 list 兼容；coverage 与单次 load 结果绑定，例如附带元信息的 list 兼容结果，不用跨请求 last_coverage 可变共享字段。原来返回普通 list 的测试替身仍应兼容，不能为新接口改坏 S05 测试。

每次 load 的 image_coverage 固定五字段：text_sources, images_seen, images_indexed, images_skipped, skip_reasons；整数非负，shape 符合 ImageCoverage。text_sources 按非空正文的原文件计数，图描述不算正文来源。images_seen 按实际观察到的去重资产计数，包含因预算/格式/vision 被跳过者；每图只计一个最终原因，images_seen=images_indexed+images_skipped。按文档/来源做预算，不能把每次调用都重新计数而突破 12 张。parser 无资产只增加 skip_reasons.parser_no_assets（单位为无法验证的源文档数），不凭空增加 images_seen/skipped；其他四类原因单位为实际跳过的图，所以全部 skip_reasons 之和不必等于 images_skipped。重复图的同一资产只处理一次、文本位置标记保留；不同源文档各自归属，不能串来源。无资产不等于“确定没有图/完全覆盖”。image_coverage_warning 是外层独立的固定安全提示（有跳过或 parser_no_assets 时必须可见）；不要向五字段对象塞额外键而破坏 schema。

每文档 12 张、单张 <=4*1024*1024 字节、<1200 字节跳过、单文档图片合计 <=12*1024*1024；聊天每轮 16 张/12*1024*1024，按原始 bytes 而非 base64 长度。边界值含等号明确。先 stat/限量读取/验证，再编码或请求模型；受限的 parser assets 不跟随软链接或越过资产根。不能改变 reading_image_budget() 的 120 张/60MiB/每页4张特殊用途。不要引入缓存、并行描述、批量 OCR、实际 KB 重建或 ZIP 上传功能。

P1-27 必须贯通：load 的局部 coverage → pipeline 本次 initialize 结果 → initializer → metadata.json 以及 ProgressTracker 的最终保存/任务事件。可通过可选 image_coverage_callback 传递，原两参数 embedding 进度回调与 bool initialize 返回值保持。metadata 合并保留旧字段，采用既有安全原子写/短事务，不把长期模型调用放进锁。最终 COMPLETED 事件、.progress.json 和 kb_config 对外 progress 均保留本次 coverage/warning；不能仅打印日志，不能在后续完成事件中被覆盖丢失，也不能带入上次任务数据。只改这条加法式投影，不重写全局 progress/manager 生命周期。initializer.py 中 CLI convenience initialize_knowledge_base 的最终 progress 合并也不能覆盖掉 coverage；测试至少覆盖科目任务最终事件和该便捷入口。有正文+图片失败允许成功但有警告；只有图且全失败/所有 parser 失败/零有效节点必须失败，不写 ready/新成功版本，旧成功版本和 S05 last_ready 保留。失败时清理本次未成功版本，不能切换当前版本后再返回失败。
