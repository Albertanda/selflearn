三、返修单元

R1：错误构造与投影遵守固定安全字段
目标：C02 的 code 对应固定安全消息、HTTP 状态和布尔 retryable，不能被任意输入覆盖。
实际证据：SubjectOperationError 的 message 只被压平/截断，传入唯一虚构 Authorization 标记后仍进入 HTTP/WS/tool payload；SubjectOutputTruncated(message=...) 同样泄漏。provider_timeout 可被构造成 http_status=200；invalid_input 的 retryable="false" 被 bool() 转成 True。
允许范围：errors.py、test_p1_03.py；必要时与同模块的 ModelOutputError/SubjectOutputTruncated 调用兼容。
处理：保留附录A的 SubjectOperationError(code, message, *, http_status, retryable, cause=None) 签名及所有必需字段。有效参数继续可用；不符合固定规格的参数可安全拒绝，或归一化成 ERROR_SPECS 的固定值。不能把“调用者应自行保证消息安全”作为 public projection 的保证。
message 必须来自固定表/明确的静态安全文案白名单；本轮直接使用 ERROR_SPECS 是最简单的处理。状态与 retryable 也按同一 code 验证，不允许 int(True)、bool("false") 等隐式转换掩盖错类型。保留 cause/diagnostics 在服务端，但不得把它们拼进对外 message/args。
safe_message 的压平/截断只改变格式，不能宣称能去秘密。禁止通过针对 sk-/Authorization 的 regex 或只删除测试标记来过关；任意虚构正文/宿主路径同样不能成为该 code 的动态对外消息。
证据：先用完全合法的基准证明构造/投影可用，再分别只改 message、http_status、retryable；检查 HTTP/WS/tool 完整序列化及 str/repr。自定义 message 不得回传，固定 code 不得变成 200；retryable 真正为 bool 且符合表。保留 23 个 code 的 Schema 和映射回归。
完成：所有构造入口和投影满足固定安全规格；不删字段、不改 Schema、不破坏已有合法调用及空截断旧异常语义。

R2：未知异常不能根据泛型或类名猜成用户错误/超时
目标：遵守附录A“未知异常 internal_error”；用户输入错误和 provider timeout 有明确的领域依据。
实际证据：任意 ValueError/TypeError/KeyError 均被改为 invalid_input/400，内部参数或状态故障会被归咎于用户；名为 TimeoutConfigurationError 的普通 RuntimeError 被映射成 provider_timeout/504。
允许范围：errors.py、test_p1_03.py。
处理：删除这两种无上下文的猜测。调用者已验证为参数错误时，应显式构造 INVALID_INPUT 等领域错误；未知内核/代码异常按 internal_error/500/false。已知 LLMReasoningBudgetExhausted、Empty、Parse、Provider、Storage 及真实 timeout 映射保持。
超时使用实际已知异常类型/继承关系，不能只看类名是否含 timeout。如果保留 httpx/OpenAI 的既有支持，用明确类型和独立正例证明；不新增依赖、不修改全局异常树。
证据：三种泛型异常及“名字像超时的非超时异常”得 internal_error；明确 INVALID_INPUT 仍 400；真实 LLMTimeoutError/TimeoutError 仍 504；真实预算异常继承及 502 code 保留。
完成：未知不会误标可重试的 provider timeout 或用户输入错；真正的已知业务错误仍按 C02 表处理。

R3：严格数字与解码失败都是具名模型错误
目标：parse_model_object 返回可用的严格 JSON 对象，不能接受非标准/非有限数字，不能漏出原生解码异常。
实际证据：{"nested":{"value":NaN/Infinity/-Infinity}} 均被接受；1e400/-1e400 被解成非有限 float；5000 位整数产生原生 ValueError。受控 decoder RecursionError 也绕过了当前只 catch JSONDecodeError 的处理。
允许范围：model_output.py、test_p1_55.py。
处理：拒绝非标准 numeric constants；检查浮点转换溢出后是否非有限，包含嵌套对象/数组。合法有限浮点、整数、中文和已有对象结构继续支持。解码/转换引起的 ValueError、RecursionError 等应转换为 ModelOutputError/invalid_model_output，保留固定服务端 reason，投影不含原文。
这不是新增任意精度数字或无界深度支持。运行时无法处理的合法极大数可以具名拒绝；禁止修改 sys.set_int_max_str_digits/sys.setrecursionlimit 或吞错返回 {} 来逃避。也不要把所有系统退出/取消异常用 except BaseException 当作模型错误。
证据：NaN/±Infinity 和浮点溢出反例；有限大浮点与合法嵌套正例；5000 位数字在受控默认整数限制下具名失败；对合法基准注入 decoder RecursionError 后具名失败。测试改变解释器限制必须在测试自身恢复，生产 parser 不改全局状态。
特别说明：协调者初版用固定 1200 层嵌套触发递归限制，但当前环境并未达到限制，该用例本身不成立；两份早期日志保留。最终权威探针改为先证明基准合法，再注入 decoder RecursionError，不要求“1200 层必须拒绝”，不要据此新造深度策略。
完成：上述失败均为 invalid_model_output/502/retryable，原始 ValueError/RecursionError 不直接逃逸；不提前做 verdict/points 领域语义校验。
