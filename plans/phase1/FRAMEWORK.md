# 第一阶段：现有功能修复与收敛框架

版本：2.0（阶段调度）；日期：2026-10-10；项目根目录：`/home/albert/selflearn/selflearn`。输入依据为 `PROJECT_AUDIT_2026-10-10.md` 和当前工作树，而不是只有 `9723f95` 的提交树。本包只定义后续执行工作，本轮没有实施业务修复。

## 1. 阶段目标与边界

目标是让现有科目、聊天、知识库、批改、考点、复习包、报告和导出具备一致且可验证的行为：资料来源正确，失败不伪装成功，不因模型失败修改学情，不写出自己的数据范围，不用陈旧图片或文件，不因并发与写入中断静默丢记录。

本阶段包括补齐原有功能的接线、异常与状态处理、存储一致性、既有图片索引适配、报告隔离、必要的裁剪残留清理和验收测试。只新增修复所需的内部辅助代码、加法式响应字段和测试；保留现有路由、数组存储和主要配置 schema。

明确排除：新的 Practice/题库子系统、相似题/间隔复习、从全部教材自动建立知识体系、跨编码器或远程 rerank、多 key 轮换、新 MCP 接入平台、上游整包升级、数据库迁移、完整后台任务调度系统、备份恢复 API、新批改 UI、模型连接 schema 重构、自动画像事实抽取扩展。导出增加元信息和已有产物是修正已有导出范围，不新增恢复流程；图片描述转文本是修通现有图像知识索引，不新增独立 OCR 产品。

## 2. 当前证据与本轮补充发现

现有基线：后端 2917 passed / 1 failed / 22 skipped，前端 403 passed，tsc 通过；唯一后端失败为固定过期时间夹具。两个服务当前未启动。六科数据在 `data/user/workspace/subjects`，公开产物在 `data/user/subjects`。已有未提交源码必须随基线一起保留。

进一步核实了原审计中需要收窄的两点：

- `LLMReasoningBudgetExhausted` 继承 `LLMProviderError`，不是 `LLMEmptyResponseError`；只 catch 后者的报告/复习接口无法覆盖全部预算失败。
- MCP SDK 声明和 PageIndex MCP 提示仍在，但本工作树没有外部 MCP client 注册链路。PageIndex REST `search` 实际提供目录概览。第一阶段让概览能力如实可用并去掉不存在的工具提示，不恢复 MCP 运输层；SDK 本阶段保留待后续依赖审查，不能继续宣称已被活跃链路使用。
- 沙箱 runner 的 SYSTEM 等级描述进程与宿主的隔离，不自动描述每次任务的数据隔离。现有 sidecar 可见共享用户目录，不能直接拿来证明报告不能读别科或别账户的数据。报告执行采用经验证的最小 bwrap profile；其他 backend 未证明任务隔离前拒绝执行。
- ReportTool 的 `review` 仍接受任意 report_path，且 Markdown 持久化只在聊天 create 路径完成。路径校验、原件不可变和两入口一致性纳入本阶段。

## 4. 粒度与依赖原则

任务卡通常只有一个行为目标，修改 1–3 个生产文件、1 个主要测试文件。存储、响应契约等共同依赖先独立实现，业务卡只接入；相互共享大文件的卡必须串行。单元的确定性来自精确输入/输出与反例，而不是“改了几行”。

每张卡独立列目标、已有证据、读取入口、允许文件与符号范围、执行步骤、测试命令、完成条件和禁止事项。卡上的依赖是必需前置，不允许为了省事跨卡实施。一个会话执行一个已授权阶段（2–6张卡）；阶段内串行完成，阶段结束一次独立审查。小卡保持编码粒度，禁止自由选阶段外任务。批改与模型解析、数据写入分开；科目作用域编码与聊天接线、检索接入分开；报告目录、沙箱、图像验证、编排、接口、核查分开。

约250行现作为阶段复杂度提醒，不机械触发人工补卡；文件范围/目标或契约确需扩大时才blocked_scope。阶段内已授权单元为集成需要作小修可以直接实现并复测。禁止顺手重构、全仓格式化、机械删所有 MCP/book/partner 字符串。
